## Context

Your 8-point UX review of the Client Admin / Super Admin portals, plus 3 fixes to the UI-structure HTML doc. All changes are frontend-only except one small backend addition (confirm-pending by ids). Everything else reuses existing components and data already returned by the API.

Key facts from exploration that shape the design:
- Filters already have a chip row + remove handlers (`Dashboard.jsx` 817-850, 1099-1115) — no URL sync, no Save view
- ReviewQA already has keyboard shortcuts (j/k/c/r/e), status chips, and `confirmAllPending` that confirms ALL pending — no flagging exists; records expose `has_geo`, `answers._duration_sec`, `has_voice` + survey `voice_required`, `answers.phone` — enough to auto-flag client-side
- No geofence radius setting exists anywhere — "GPS outside geofence" becomes "GPS missing/invalid" (`has_geo === false`) unless a radius is added later
- The Ward ward→AC logic and quota numbers are server-provided; quota wording is scattered across 7 surfaces
- AdminSurveys detail is a vertical card stack with an inline `CopyWebFillLink` — a Share tab slots in cleanly
- AdminCompanies + AdminClientAdmins both call `listUsers()`+`listCompanies()` and share the same card-list pattern; AdminContactRequests/Seats/Errors/Audit are small table/card screens — all merges are low-risk

### 5 · Review QA flagged queue (ReviewQA.jsx + routes/submissions-crud.ts)
- Client-side auto-flags per pending record (pure helper `src/components/reviewFlags.js`):
  - 📍 **No GPS** — `has_geo === false`
  - ⏱ **Very fast** — `answers._duration_sec < 60` (constant, adjustable)
  - 📞 **Duplicate phone** — same `answers.phone` on another loaded record
  - 🎙 **Missing audio** — survey `voice_required` && `!has_voice`
- New filter row: **Needs attention (default) / Flagged / Clean / All** on top of the existing status chips.
- Record card shows flag chips; **Confirm-all (batch) sends only unflagged ids**: backend `POST /api/submissions/confirm-pending` accepts optional `{ ids: [...] }` (bounded 500) and confirms only those (routes/submissions-crud.ts — one param check).
- Keyboard shortcuts stay (c/r/e/j/k) — add `f` = jump to next flagged record.
